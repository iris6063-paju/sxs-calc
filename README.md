# 소드 x 스태프 전투 계산기 (비공식)

직업 · 공격 · 방어 · 생명 · 속도 · 전투스킬을 입력하면 몬테카를로 시뮬레이션으로 **승리 확률**을 계산하는 팬 제작 도구입니다.
1:1, 다대일, 다대다(팀 구성), 몹 지정을 지원하고, 대표 전투 한 판을 3D 디오라마에서 재생합니다.

- **전투 스킬 4칸** (칸 순서 = 사용 순서, ▲▼로 순번 변경) · **비법 4칸** · **판타몬**(지원 스킬 + 성년 실체화, 공격·방어·생명·속도 입력)
- **프리셋**: 지금 구성(팀 · 모드 · 설정)을 이름을 붙여 브라우저에 저장하고 불러오기 · 덮어쓰기 · 삭제합니다. JSON 파일로 내보내고 가져올 수 있습니다(같은 이름은 번호를 붙여 합침)
- **고급 능력치 = 게임 능력치 화면**: 캐릭터마다 서브 랭크(41단계)를 고르고, 치명타율 · 치명타 저항 · 막기율 · 명중은 「% + 수치」, 치명타 대미지 · 막기 대미지 저항은 「% + 고정 수치」, 효과 적중 · 효과 저항은 수치, 원소 친화력 · 가호는 원소별로 넣습니다(물리는 다섯 원소의 평균). PvP 대미지 보너스 · 저항, 치유 효과도 있습니다. 예전 저장 구성은 새 칸으로 옮겨 불러옵니다
- **소환 · 설치 스킬**: 바위 정령 · 꼬마 나무정령 · 화염 늑대 · 늪 도룡뇽 · 열광의 토템 · 거울 분신 · 불꽃요정 · 보이드 커스 룬 · 유성 화염의 작열 바닥 · 열상을 게임 자료(purrwikimania.com 시뮬레이터 자료)대로 전투와 3D 재생에 반영합니다
- **전투 불러오기**: 환상계단 585층, 일일 던전 28종(방별), 길드 토벌(길드 보스) 1~460층 전체, 신수 시련 84단계 — 길드 토벌·신수 시련은 층·단계별 보스 능력치를 게임 공식(클라이언트 계산식)으로 미리 계산해 담았습니다
- **배틀 화면**: 행동 단위 타임라인(대미지 막대 · 쓰러짐 표시, 끌어서 이동), ◀/▶▶ 한 행동씩 보기, 끝으로, 진행 설명 한 줄, 전장 효과 칩(균형의 미 · 라운드 제한 · United We Stand 등), 3D 유닛 머리 위 상태 칩, 유닛 상태 패널(생명 · 실드 · 상태 · 중첩 · 남은 턴), 줄을 누르면 그 장면부터 다시 보는 전투 로그, 결과 비율대로 고른 다시 볼 전투 10판, 미니맵에서 끌어 정하는 시작 위치, 위에서 보기 시점, 전장 바닥 8종(기본: 콜로세움) — 「결투장 (게임풍)」은 게임 전투 화면(purrwikimania.com 결투 시뮬레이터 화면 참고)처럼 모래색 체크 타일과 갈라진 땅 타일로 꾸민 바닥이고, 위에서 보기와 함께 쓰면 게임과 비슷한 시점입니다(게임 그림은 쓰지 않고 코드로 그림). 소환수는 툰 모델, 불꽃요정은 떠 있는 불씨, 작열 바닥은 빛나는 칸으로 나옵니다
- **몹 스킬 아이콘**: 몹 카드의 스킬 · 비전 목록에 게임 아이콘(`assets/mobskills/`, 39종)을 표시합니다
- **몹 비전(패시브)**: 몹 · 보스 비전 75종 중 59종을 전투에 반영합니다(원소체 · 면역, 반격, 누적 대미지 광역기, 격노, 중첩형 대미지 감소, 자폭 등). 신수 · 레이드 보스 비전은 게임 자료의 계수 · 수치입니다. 수치가 공개되지 않은 12종은 추정값이며 「몹 비전 추정값 반영」으로 끌 수 있고, 소환 등 16종은 몹 카드에 ⚠로 표시합니다
- **몹 · 보스 3D 모델(49종)**: 몹 그림 종류 42가지와 보스 7종(폭풍 그리핀 · 불사조 · 야마타노 오로치 · 태고의 용 · 은하 메카 · 욜드라 · 혼돈의 폭군)은 새로 만든 콘셉트 그림(Higgsfield z_image)을 Tripo 이미지 → 3D로 바꾼 텍스처 모델입니다. Blender(`Desktop\blender`, 일괄 처리)에서 정면을 맞추고 삼각형을 몹 5,000 · 보스 9,000개로 줄이고 텍스처를 512 · 1024px로 줄여 Draco 압축 GLB(평균 85 KB, 49종 4.2 MB)로 내보냈습니다. 같은 툰 셰이딩 · 외곽선을 입히고, 몹마다 옅은 색조를 더해 같은 종류도 구분됩니다. 전투에 나오는 모델만 그때 불러옵니다. 게임 그림은 쓰지 않았습니다
- **콜로세움 전장(기본 바닥)**: `tools/blender_arena.py`가 Blender에서 돌 원형 경기장(단상 · 성가퀴 벽 · 팀 색 깃발 기둥 · 화로 · 뒤쪽 성문 탑 · 수정 · 나무)을 코드로 지어 `assets/models/env_colosseum.glb`(86 KB)로 내보냅니다. 전투 기록 모니터는 성문 앞에 그대로 둡니다. 예전 숲 섬은 「숲 섬」 바닥으로 고를 수 있습니다
- **영웅 3D 모델(6종)**: 전사 · 마법사 · 기사 · 투사 · 주술사 · 현자 계열은 사용자의 SD 시트 4방향 그림으로 Higgsfield(Meshy 다중 이미지 → 3D, 텍스처 · 뼈대 포함)에서 만든 모델(`assets/models/<디자인>.glb`, 각 1.3~1.4 MB로 줄임, 목록은 `assets/models/index.json`)을 씁니다. `js/glbmodel.js`가 같은 툰 셰이딩 · 잉크 외곽선을 입히고, 기존 동작 코드(대기 · 이동 · 공격 · 스킬 · 피격 · 쓰러짐)를 모델 뼈대에 옮겨 움직입니다. 생성 모델은 긴 머리가 팔과 붙어 있는 경우가 많아(기사의 땋은 머리, 마법사 계열의 긴 머리) 팔은 A자 자세 가까이 두고 절반 세기로 움직이고, 짧은 머리의 전사는 더 크게, 책 · 지팡이 쪽으로 팔 뼈대가 잡힌 주술사 · 현자는 거의 움직이지 않습니다(`TUNE`). 불러오지 못하면 코드로 만든 모델로 돌아갑니다. 모델 확인: `tools/toon_viewer.html?ids=glb:knight,knight` (`&raw=1`은 생성 그대로의 자세)
- **카툰 렌더링 3D**: 전투 장면의 캐릭터 · 몹 · 보스는 GPT 6.1 sol이 설계한 3D 모델(`assets/toon/*.json`, 프리미티브 부품 목록)을 `js/toon.js`가 툰 셰이딩(3단 명암) · 잉크 외곽선 · 애니메 눈(표정 변화)으로 그립니다. 영웅 6종은 SD 시트 그림을 참고 이미지로 넣어 설계했고, 관절(다리 · 팔 · 손 · 머리 · 망토)이 대기 · 이동 · 공격(검 휘두르기 / 쌍검 / 지팡이 · 마도서 내밀기) · 스킬(회전 베기 · 방패 강타 · 두 손 영창) · 피격 · 쓰러짐 동작을 합니다. 몹은 그림 종류 42가지 모델을 몹마다 재채색해 쓰고, 신수 6종(폭풍 그리핀 · 불사조 · 야마타노 오로치 · 태고의 용 · 은하 메카 · 욜드라)과 레이드 보스 혼돈의 폭군(게임 아이콘을 참고 이미지로 사용)은 전용 보스 모델입니다(날개 · 목 · 꼬리 관절이 움직임). 섬 · 나무 · 바위도 같은 툰 셰이딩과 외곽선으로 맞췄습니다
- **캐릭터 SD 그림**: 18직업은 사용자가 제공한 SD 에셋 개발 시트 6종(전사 · 마법사 · 기사 · 투사 · 주술사 · 현자, 전직 계열은 같은 그림)에서 잘라낸 스프라이트(`assets/sheets`)로 그립니다. 전투에서는 대기 8 · 이동 6 · 공격 6 · 스킬 8 · 피격 6프레임이 행동에 맞춰 재생되고(단일 대상 = 공격, 범위 · 지원 = 스킬, 맞으면 피격, 이동 · 도약 중 이동), 직업별 이펙트(검격 · 쌍검 아크 · 방패 돌진 · 마법 화살 · 마법진 · 치유의 빛 · 피니시 등)가 단일 공격 · 투사체 · 범위 · 지원 · 처치에 맞춰 나옵니다. 유닛 상태 패널에는 표정 아이콘(기본 · 신남 · 놀람 · 당황 · 화남 · 졸림 등)이 전투 상황에 따라 바뀌고, 캐릭터 카드에는 대기 애니메이션과 방향 시트(정면 · 3/4 · 측면 · 후면)가 나옵니다. 승급 직업(3차 이상)은 오라가 더해집니다
- **몹 그림**: 몹 42종은 GPT 6.1 sol이 그린 SVG(`assets/gpt`)를 재채색해 애니메이션합니다(시트를 불러오지 못하면 영웅도 이 SVG 리그로 대체)
- **공식 명칭 · 아이콘**: 전투 스킬 118종 · 비법 114종의 한국판 이름 · 설명 · 아이콘(`assets/skills/skill_<ID>.webp`)과 직업명, 능력치 · 상태 이상 용어를 한국판 게임 리소스 기준으로 표기합니다(소드X스태프허브 스킬 도감 대조)

> 게임 개발사·퍼블리셔와 무관한 비공식 도구입니다. 결과는 커뮤니티가 정리한 공식에 기반한 추정치입니다.

## 실행

빌드 과정이 없는 정적 사이트입니다. ES 모듈과 Web Worker를 쓰므로 `file://`로 직접 열지 말고 로컬 서버로 여세요.

```bash
node serve.mjs
```

브라우저에서 `http://localhost:5173` 을 엽니다. (포트 변경: `PORT=8080 node serve.mjs`)

엔진 점검:

```bash
node tools/test_engine.mjs
node tools/test_extra.mjs
node tools/test_passives.mjs
node tools/test_pets.mjs
node tools/test_moves.mjs
node tools/test_raid.mjs
node tools/test_bosses.mjs
node tools/test_stats.mjs
node tools/test_summons.mjs
node tools/test_charms.mjs
node tools/test_pvp.mjs
node tools/test_mobskills.mjs
```

## 배포

폴더 전체를 그대로 올리면 됩니다. 모든 경로가 상대 경로라 하위 경로(`https://example.com/sxs/`)에서도 동작합니다.

| 호스팅 | 방법 |
| --- | --- |
| GitHub Pages | 저장소에 푸시 → Settings › Pages › Branch 지정 (루트) |
| Netlify / Cloudflare Pages / Vercel | 빌드 명령 없음, 출력 디렉터리 = 저장소 루트 |
| 일반 웹서버 | 폴더 복사. `.js`가 `text/javascript`, `.webmanifest`가 `application/manifest+json`으로 나가면 충분 |

외부 요청은 글꼴 2종(Pretendard, JetBrains Mono)뿐이며, 막혀 있어도 시스템 글꼴로 동작합니다. three.js는 `vendor/`에 포함되어 있습니다.
`tools/` 폴더는 개발용이므로 배포에서 빼도 됩니다.

## 계산 방식 요약

- **행동 순서**: 행동 간격 = 100000 ÷ √속도. 한 턴에 최대 4칸 이동 후 준비된 전투스킬을 슬롯 순서대로 모두 시전.
- **원거리 거리 유지(마법사 계열)**: 게임 AI(SkillAiCfg)대로, 거리를 유지하는 원거리 스킬(RangeType Far, DontKeepDistance 아님 — 47종)이 그 턴의 마지막 시전이면 「가장 많이 맞히는 위치」 가운데 가장 가까운 적에게서 먼 칸(SaferPos, 6칸 넘으면 거꾸로 셈)에서 쏩니다. 그래서 마법사는 스킬 사거리 끝에서 공격합니다. 그 밖에는 이동이 가장 짧은 칸을 고릅니다.
- **고급 능력치(능력치 화면)**: % 뒤 「+ 수치」는 수치 ÷ 그 서브 랭크의 기준값(BaseCritRatePercentValue)만큼 %에 더합니다. 치명타 대미지 고정 수치는 치명타 때 스킬 계수 × 배율을 곱해 더하고(방어력 항 밖), 막기 대미지 저항 고정 수치는 막을 때 같은 방식으로 뺍니다. 효과 적중 · 저항은 수치 ÷ 기준 효과 저항(BaseEffectRate)입니다. 랭크를 비워 두면 레벨 기준값을 씁니다.
- **소환수**: 능력치 = 시전자 능력치 화면 값 × 계승 비율(summon_monster_add_prop) × 스킬 랭크 계수(summon_rank_additive_factor) + 레벨 고정치(커브 × 랭크 계수) — BattleFormulaHandler.CalcSummonMonsterInheritProp. 치명 · 원소 등 나머지는 그대로 이어받습니다. 소환 즉시 시전자 바로 다음에 행동하고(SummonImmediateRound), 자기 턴이 끝날 때마다 수명을 1 줄입니다. 잠행 소환수는 다른 대상이 있으면 주 대상으로 골라지지 않습니다. 소환수는 승패 · 라운드 수에 들어가지 않고 버프를 받지 않습니다. 다시 소환하면 빈 자리부터, 둘 다 서 있으면 가장 오래된 쪽을 바꿉니다.
- **거울 분신**: 6칸 내 적(큰 몸집 → 낮은 생명 순) 편에 서고, 그 적의 생명 16% · 방어 60% 등을 이어받습니다. 분신이 잃은 생명만큼 연결된 적이 고정 대미지로 잃고(실드는 먼저 받음), 아군 AI는 분신을 대상 1명 더 맞히는 것으로 셉니다(VoodooDollCountWeightChange). 시전자 턴 3번 뒤, 또는 연결된 적이나 시전자가 쓰러지면 사라집니다.
- **대미지**: (공격력×계수+고정값) × 공격력/(공격력+방어력) × 원소 배율 × (1+대미지 보너스+PvE 대미지 보너스)/(1+대미지 저항+PvE 대미지 저항) × 막기·치명타 × 레벨 · 랭크 보정.
- **몹의 원소 능력치**: 몹도 게임 커브의 원소 친화력 · 가호(원소별)와 원소 · 물리 마스터리 · 저항을 가집니다.
  - 몹 쪽 기준값은 자기 서브 랭크의 게임 기준값(`tools/rankbases.mjs`)입니다.
  - 고정 능력치 블록은 20 · 28칸 형식이고, 예전 14칸 저장 구성은 불러올 때 같은 층 · 단계의 새 블록으로 바꿉니다.
  - 이전에는 몹이 모두 0이라, 마스터 신수의 원소 공격이 실제보다 약 1.7배 약하고 우리 원소 공격은 약 1.7배 강했습니다.
- **레벨 · 랭크 보정**: 레벨 차 1~4는 레벨당 4%, 5~20은 16%, 21 이상은 10%입니다. 몹 전투에만 적용하고 대전(PvP)에는 적용하지 않습니다(2026-11-21 수정).
  - PvE에서 「내 랭크」를 고르면 게임의 랭크 차이 배율 1 + |차이|를 적용합니다(BattleFormulaHandler.DamageRankOffsetDamage, 적 자료의 `rankDmg`). 예: 챔피언 vs 마스터 ×81.
  - 환상계단은 `demonDmg` 표가 더해집니다.
- **판정**: 실명 → 회피 → 막기 → 치명타. 막기 시 ÷max(1.5, 1+막기 대미지 저항−명중), 치명타 시 ×max(1.3, 1+치명타 대미지−치명타 저항).
- **유일 효과(2026-11-21)**: 「해당 효과는 유일합니다」인 효과(허공의 축복 · 질풍 가속 · 돌파 의지 · 영혼 장막 · 철벽 방어 · 불길한 징조)는 다른 캐릭터가 또 걸어도 한 개만 남고 새것으로 바뀝니다(게임의 ActionBehOfSameStatus Immediate). 같은 종류라도 다른 스킬의 효과(마법 갑옷과 영혼 장막의 대미지 감소 등)는 함께 적용됩니다. 전에는 철벽 방어가 두 명이면 두 번 적용됐고, 같은 종류의 다른 스킬 효과는 서로 지워졌습니다(`tools/test_charms.mjs`).
- **진영 공정성(2026-11-21)**: 같은 조건의 칸 · 방향 · 조준점이 여럿이면 두 진영 모두 자기 진영 기준으로 같은 쪽(앞 · 뒤)을 고릅니다(전엔 위쪽 우선이라 한 진영은 앞으로, 다른 진영은 뒤로 갔습니다). 속도가 똑같은 유닛의 전투 전 시전(도발 · 버프)은 매 전투 무작위 순서입니다(전엔 항상 아군 먼저). 같은 4명끼리의 4v4 미러전이 68% : 32%에서 50% 근처로 맞춰졌습니다(`tools/test_pvp.mjs`).
- **PvP 전장 보정**: 게임의 PvP 전장 효과 세 가지입니다. 균형의 미 I은 캐릭터가 받는 대미지 ×0.2, 소환수 ×0.6, 제어 효과 확률 ⅓입니다. 균형의 미 II는 판마다 정해지는 스킬 대미지·치유·실드 배율입니다(아래). 빠른 결착은 12라운드부터 라운드마다 대미지 +10%p, 치유·실드 −20%입니다.
- **균형의 미 II(PvP 배율, 2026-11-21)**: 게임의 PVPSkillPropsScaleOnBattleProcessor를 purrwikimania.com 팀 시뮬레이터가 읽은 대로 옮겼습니다. 배율 = 생존 비율 × 스킬 랭크 × 랭크 균형이고, 전장 효과 칩에 값이 나옵니다.
  - 생존 비율: 필드 캐릭터 중 가장 낮은 「출력 ÷ 생존」 비율(공격력² ÷ (공격력+방어력) ÷ 체력 × 치명타 · 막기 · 원소 · 대미지 보너스)이 0.1을 넘으면 0.1 ÷ 비율입니다.
  - 스킬 랭크: 장착한 기술·비법의 평균 랭크(진영마다 가장 높은 캐릭터, 두 진영 평균)가 서버 일수로 정해지는 기대 랭크(0일 7 … 90일부터 17)보다 높으면 감소합니다. 서버 일수는 설정에서 바꿉니다(기본 150일).
  - 랭크 균형: 패러곤은 레벨에 따라 46.6~99.5%, 세인트는 83~99%, 그 밖의 랭크는 100%입니다.
- **받는 쪽 랭크의 스킬 대미지 감소(2026-11-21, PvP · PvE 모두)**: 게임의 Damage()는 (공격력 × 계수 ÷ (1 + PlayerSkillDmgReduceScale) + 고정값) × 공격력÷(공격력+방어력) … ÷ (1 + ProSkillDmgReduceScale)입니다. 두 값은 받는 쪽 랭크의 기준값입니다.
  - 정예 II부터 붙고, 숙련 III ÷1.14 · ÷1.14, 마스터 I ÷1.15 · ÷1.46(합 ÷1.68), 패러곤 ÷2.78, 세인트 ÷3.27, 에테리얼 이상 ÷3.82입니다.
  - 랭크를 고르지 않은 캐릭터는 그 레벨의 가장 낮은 서브 랭크로 봅니다(예: Lv.130 → 챔피언 III).
  - 몹은 자기 능력치 곡선의 값을 씁니다(곡선 값이 없는 몹은 서브 랭크의 값).
  - 치유·실드 스킬에는 게임 자료의 PvP 비율이 걸립니다: 치유 기술 5종과 실드 기술 ×0.45, 이 계산기가 반영한 치유·실드 비법 12종(오버힐 · 정화의 갑옷 · 공허 환영 · 리바이벌 · 불굴의 의지 등) ×0.45~0.56.
  - 분신이 받은 대미지는 소환수 배율(×0.6)이 걸린 뒤 연결된 대상에게 그대로 넘어갑니다(게임: CustomDamageWithoutBattleFormula).
- **격자**: 21×20 보드, 5칸 폭 진형 자동 배치, 「많이 맞히는 위치 → 짧은 이동 → 낮은 체력 비율」 순으로 대상 선택.
- **몹 크기**: 신수 시련의 신수는 게임 데이터(GridTransformComponent.BodyRangeInfos, purrwikimania.com 시뮬레이터 자료)의 몸체를 씁니다. 폭풍 그리핀 · 불사조 · 욜드라는 4×4(16칸), 야마타노 오로치 · 태고의 용 · 은하 메카는 5×5(25칸)입니다. 같은 자료의 레이드 보스 혼돈의 폭군도 5×5입니다. 그 밖의 보스는 공개된 몸체 자료가 없어 2×2(4칸)로 가정했습니다. 근거는 게임 돌진 스킬 설명 「4칸보다 큰 적은 관통 불가」로, 4칸짜리 몸체가 있다는 뜻입니다. 거리 · 사거리 · 범위 판정은 몸체 중 가장 가까운 칸 기준(맨해튼 거리)이고, 큰 몸체는 몸 전체가 들어가는 칸에만 섭니다.
- **다단 히트**: 「대형 대상은 여러 번 맞을 수 있음」 스킬은 게임 데이터에서 범위가 몇 개의 타격 구역(HitCfg)으로 나뉘어 있습니다. 대형 대상은 몸체에 닿는 구역마다 1회씩 맞습니다(`tools/hitparts.mjs`).
  - 수룡진: 3칸 × 4줄, 최대 4회. 2×2 보스는 보통 2회입니다.
  - 천공의 환검: 4칸 × 3열.
  - 새벽의 균열: 안쪽 2칸 / 바깥 3칸 고리, 최대 2회.
  - 「같은 대상에게 맞을 때마다 대미지 X% 감소」는 두 번째 타격부터 곱해서 적용합니다.
  - 튕김 · 연쇄 공격은 대형 대상의 다른 칸으로 다시 튈 수 있습니다(추정).
  - 「대형 대상 우선」 스킬은 대형 대상이 든 위치를 먼저 고릅니다.
- **신수 6종 · 혼돈의 폭군 스킬(게임 자료)**: 보스 스킬 정의(purrwikimania.com 시뮬레이터 자료 `assets/duel.json`의 `bosses`)를 그대로 옮겼습니다. `tools/bosskits.mjs`(한국어 이름 · 설명 · 형태 세트)와 build_extra가 만듭니다.
  - 담긴 정보: 타격 구역(HitCfg 칸), 타당 계수, 쿨다운, 넉백 · 끌어당김 · 도약, 무작위 낙하, 상태 이상, 생명 50% 조건, 각성 · 형태 세트.
  - 엔진은 한 타씩 처리하고, 각 타격이 맞히는 대상은 그 타격이 떨어질 때 정합니다(게임의 동작).
    - 그래서 폭풍 그리핀 「사이클론 휠」은 6타마다 1칸 넉백되고 범위가 한 줄씩 늘어나, 밀린 대상이 최대 6번 맞습니다.
  - 시전 규칙
    - 영역은 몸체 중심을 기준으로 회전하고(4×4 몸체도 빈틈 없음), 시전 방향은 조준 칸을 따릅니다.
    - 준비된 스킬은 순서대로 모두 씁니다.
  - 형태 · 단계
    - 태고의 용 · 은하 메카는 생명이 처음 50% 이하가 되면 빛 스킬 세트로 바뀝니다.

- 몹 스킬 계수·쿨다운은 공개 자료가 없어 턴당 1스킬 · 계수 100%로 가정(화면에서 조정 가능). 격노 · 각성 등 특정 상태 전용 보스 스킬도 일반 순환에 넣었습니다.
- **대미지가 없는 몹 스킬(2026-11-23)**: 자기 · 아군 강화, 치유, 실드, 반격 · 방어 자세, 격노, 자세 전환, 설치(폭탄 · 거미줄 · 작열), 오라, 소환 · 분신 47종을 `tools/mobskills.mjs` 표로 반영합니다. 게임 자료(purrwikimania.com `assets/enemies/skills.json`)에는 이 스킬들의 이름 · 설명 · 아이콘만 있어, 설명에 없는 크기는 추정값입니다(「몹 비전·스킬 추정값 반영」을 끄면 빠집니다).
  - 추정값: 방어력 · 공격력 증가 +30%(아군 공격력 +20%, 「대폭」 +60%), 막기율 · 회피율 · 치명타율 +30%p(「대폭」 막기율 +60%p, 치명타율 · 명중 +50%p), 미풍의 축복 방어력 −30%, 자기희생 다음 스킬 +50% · 방어력 −30%, 지하의 은총 중첩당 +5%, 도올 격노 공격력 · 방어력 +20%(신수 격노와 같은 크기). 치유는 시전자 최대 생명의 10%(빠른 회복 15%), 수분 보충은 턴당 5%, 실드는 시전자 최대 생명의 15%(얼음 방패 10%) · 2턴, 주술: 공허는 현재 생명 20%를 실드로 전환. 들불의 작열은 2턴.

## 데이터 갱신

`tools/build_data.mjs` 는 내려받아 둔 위키 페이지(스킬 표, 스탯 기준표, 적 데이터 JSON)를 읽어 `js/gamedata.js`를 다시 만듭니다.
패치 후 수치가 바뀌면 같은 페이지를 다시 받아 실행하세요. 한글 이름과 스킬별 모델링 예외는 스크립트 안의 `OV`, `KO_MOB` 표에서 고칩니다.

```bash
node tools/build_data.mjs <내려받은_폴더> js/gamedata.js
```

스크립트가 읽는 파일 이름(모두 `https://www.purrwikimania.com` 기준, 원본 페이지는 저장소에 포함하지 않습니다):

| 저장할 파일명 | 경로 |
| --- | --- |
| `skills.html` | `/combat/skills` |
| `base-stats.html` | `/base-stats` |
| `stat-conversion.html` | `/stat-conversion` |
| `curves.json` | `/assets/curves.json` |
| `enemies_index.json` | `/assets/enemies/_index.json` |
| `enemy_skills.json` | `/assets/enemies/skills.json` |
| `fantasia_fa1.json` ~ `fantasia_fa4.json` | `/assets/enemies/fantasia_fa1.json` … |
| `curve_0.json`, `curve_1.json`, `curve_2.json`, `curve_st.json` | `/assets/enemies/curve_0.json` … |

`tools/build_extra.mjs <위키_폴더> <추가_폴더> js/gamedata2.js` 는 위 폴더에 더해 `conquest_gc.json`, `crucible_cr*.json`, `dungeons_dd*.json`, `chaos_ci.json`(혼돈 침공 레이드), `curve_3.json` ~ `curve_6.json`(모두 `/assets/enemies/`), 보스 스킬 정의 `duel.json`(`/assets/duel.json`)과,
추가 폴더의 `pets.html`(`/pets`), `metahub_database.html`(`https://metahub.wiki/swordxstaff/ko/database/`, 한국판 스킬 · 비법 이름 · 설명 · 아이콘 주소), `metahub_builder.html`(`…/ko/builder/`, 보조 대조용)을 읽습니다.

아이콘은 `https://api.iconify.design/game-icons.json?icons=이름,이름,…` 응답을 저장해 `node tools/build_icons.mjs <json> js/icons.js` 로 만듭니다.
